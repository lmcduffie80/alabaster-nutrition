# Multiple Businesses Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every record belongs to a business, and Postgres row-level security keeps businesses apart. Alabaster becomes business 1 with no visible change.

**Architecture:**
- Every table gets `business_id`, defaulted from the transaction setting `app.business_id`.
- A `NOLOGIN` role, `tenant_app`, has RLS policies on `business_id`. Request code reaches the database only through `withBusiness(id, tx => …)`, which sets that setting and the role for one transaction.
- A small `system` module handles the pre-business lookups (email → businesses, kiosk token → device).

**Tech Stack:** Next.js 16 App Router, Drizzle 0.45, Postgres (Neon in production, PGlite in tests), Clerk, Vitest.

Spec: `docs/superpowers/specs/2026-11-10-multi-business-design.md`

## Task 2: Migration hand edits

- [ ] For every `ADD COLUMN "business_id" … NOT NULL DEFAULT …`, rewrite it as three statements:
  ```sql
  ALTER TABLE "x" ADD COLUMN "business_id" integer;
  UPDATE "x" SET "business_id" = 1;
  ALTER TABLE "x" ALTER COLUMN "business_id" SET NOT NULL, ALTER COLUMN "business_id" SET DEFAULT nullif(current_setting('app.business_id', true), '')::int;
  ```
  Order them so unique constraints exist before the composite foreign keys that reference them.
- [ ] `business.id`: drop the default, `ADD GENERATED BY DEFAULT AS IDENTITY (START WITH 2)`.
- [ ] Append the database walls:
  ```sql
  DO $$ BEGIN CREATE ROLE tenant_app NOLOGIN; EXCEPTION WHEN duplicate_object THEN NULL; END $$;
  GRANT tenant_app TO CURRENT_USER;
  GRANT USAGE ON SCHEMA public TO tenant_app;
  GRANT SELECT, INSERT, UPDATE, DELETE ON <each business table> TO tenant_app;
  GRANT SELECT, UPDATE ON "business" TO tenant_app;
  ALTER TABLE <each> ENABLE ROW LEVEL SECURITY;
  CREATE POLICY tenant_isolation ON <each> USING (business_id = nullif(current_setting('app.business_id', true), '')::int) WITH CHECK (business_id = nullif(current_setting('app.business_id', true), '')::int);
  CREATE POLICY tenant_isolation ON "business" USING (id = nullif(current_setting('app.business_id', true), '')::int);
  ```
- [ ] Run `pnpm exec vitest run`. Expected: tests fail on a null `business_id`, which Task 3 fixes.

## Task 3: `withBusiness` and the database-wall tests

- [ ] `web/src/db/tenant.ts`:
  ```ts
  export type Tx = Parameters<Parameters<Db["transaction"]>[0]>[0];
  export async function withBusiness<T>(db: Db, businessId: number, work: (db: Db) => Promise<T>): Promise<T> {
    return db.transaction(async (tx) => {
      await tx.execute(sql`select set_config('app.business_id', ${String(businessId)}, true)`);
      await tx.execute(sql`set local role tenant_app`);
      return work(tx as unknown as Db);
    });
  }
  /** Tests only: the whole (single) connection acts as one business. */
  export async function asBusiness(db: Db, businessId: number | null) { … session-level set_config + set role / reset role }
  ```
- [ ] `web/src/db/tenant.test.ts`: two businesses with an item each. As business 1:
  - an unfiltered select sees one item;
  - inserting with `business_id = 2` throws;
  - updating 2's item changes 0 rows;
  - a delivery line pointing at 2's item fails its foreign key.

  With no business set, the select returns `[]`.
- [ ] `web/src/test/businesses.ts`: `openBusinessDatabase()` opens PGlite, creates businesses 1 and 2 through `createBusiness`, and returns `{ db, use(id) }`.
- [ ] Update the setup of every existing server test to `await asBusiness(db, 1)` after creating business 1. Run `pnpm exec vitest run`. Expected: all pass.
